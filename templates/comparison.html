01

Compare the same detector selection

All builds contain the same minimal pipeline: an OTLP receiver → resource detection processor (RDP) → debug exporter. “All detectors” means every RDP detector is compiled; it does not mean the full Contrib distribution.

The two selected builds compile the same set of detectors. Extra savings come from removing configuration dependency paths, not from choosing enable tags instead of omit tags. This experiment compares the complete changes; it does not measure each dependency fix separately.

02

What this PR adds to upstream main

A resource detector adds facts about where telemetry runs, such as a cloud region or host name. Build tags choose which implementations Go compiles. The YAML detectors list chooses which compiled implementations run; omitting a detector from YAML does not remove its code.

Upstream already provides each detector’s implementation and an omitted version, selected by omit_detector_* tags. This PR reuses those files. It adds remove_all_resourcedetection_detectors plus individual enable_resourcedetection_*_detector tags, so a builder can start empty and name only the required detectors.

Both tag styles remain supported. An omit tag wins if it conflicts with an enable tag. Without global removal, enable tags do not trim a default build. Starting with global removal also leaves newly added detectors excluded until explicitly enabled.

Go imports code in packages. A configuration field or default can keep a provider library (an SDK) reachable even when its detector implementation is excluded. The PR breaks three such connections:

Kubernetes configuration

Put connection fields and validation in a small package without Kubernetes client imports. Included detectors convert these settings to the existing client configuration. Other components keep their existing client type.

GCP resource helpers

Move helpers that use the GCP detector library out of the always-compiled metadata package. The helpers now compile with the GCP implementation, so excluded GCP code no longer keeps that library reachable through configuration.

EC2 retry defaults

Declare the same two defaults locally: three attempts and a 20-second maximum backoff. Configuration no longer imports the AWS retry package just for these values.

Typed configuration remains available in every build, with the same YAML fields. A factory filters unavailable constructors and reports an error if YAML selects an excluded detector. Builds without env must override the default detectors: [env].

How to build and configure a selected Collector

For Oracle Cloud, pass these tags to the Collector build, then set detectors: [oraclecloud] in the resource detection processor configuration. The tags select source files at build time. The YAML list selects available detectors at runtime.

remove_all_resourcedetection_detectors,enable_resourcedetection_oraclecloud_detector

Build tags do not remove requirements from go.mod or select independent dependency versions. Other Collector components can still require libraries excluded from RDP. Unknown build tags are silently ignored by Go, so spelling matters.
