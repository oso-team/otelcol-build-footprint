03

How the work fits together

A resource detector adds facts about where telemetry runs, such as a cloud region or host name. Build tags choose which implementations Go compiles. The YAML detectors list chooses which compiled implementations run; omitting a detector from YAML does not remove its code.

Codeboten’s upstream work provides each detector’s implementation and an omitted version, selected by omit_detector_* tags (for example, #51777). That foundation already removes substantial code. PR #52063 reuses those files. It adds remove_all_resourcedetection_detectors plus individual enable_detector_* tags, so a builder can start empty and name only the required detectors.

Both tag styles remain supported. An omit tag wins if it conflicts with an enable tag. Without global removal, enable tags do not trim a default build. Starting with global removal also leaves newly added detectors excluded until explicitly enabled.

Go imports code in packages. A configuration field or default can keep a provider library (an SDK) reachable even when its detector implementation is excluded. The follow-up removes three such paths. This page measures their combined effect with the parent PR; it does not attribute each byte to an individual change:

Kubernetes: lightweight configuration

Put connection fields and validation in a small package without Kubernetes client imports. Included detectors convert these settings to the existing client configuration. Other components keep their existing client type. Merged in #52313.

GCP: implementation helpers behind tags

Move helpers that use the GCP detector library out of the always-compiled metadata package. The helpers now compile with the GCP implementation, so excluded GCP code no longer keeps that library reachable through configuration.

EC2: SDK-free retry defaults

Declare the same two defaults locally: three attempts and a 20-second maximum backoff. Configuration no longer imports the AWS retry package just for these values. Merged in #52170.

Where things stand today: the EC2 and Kubernetes child PRs have already merged upstream. The larger savings here belong to the combined effort, not to parent PR #52063 alone against today’s main. See that smaller, current-main comparison separately.

Typed configuration remains available in every build, with the same YAML fields. A factory filters unavailable constructors and reports an error if YAML selects an excluded detector. Builds without env must override the default detectors: [env].

How to build and configure a selected Collector

For Oracle Cloud, pass these tags to the Collector build, then set detectors: [oraclecloud] in the resource detection processor configuration. The tags select source files at build time. The YAML list selects available detectors at runtime.

remove_all_resourcedetection_detectors,enable_detector_oraclecloud

Build tags do not remove requirements from go.mod or select independent dependency versions. Other Collector components can still require libraries excluded from RDP. Unknown build tags are silently ignored by Go, so spelling matters.

Reproduce and verify


Every measured build uses the same Go and OCB executables, dependency versions, minimal Collector composition, platform and build flags. OCB is the OpenTelemetry Collector Builder. Controlled reconstruction: stages 1 and 2 use pinned upstream code with only the EC2 #52170 and Kubernetes #52313 Go/schema changes reversed. The public patch restores the SDK-coupled configs while retaining the omission machinery and all dependency pins. Stage 3 uses the pinned parent PR with both prerequisites included. This isolates the combined changes from unrelated dependency upgrades.


The 42 completed-work binaries are reused from the version-matched refresh, with their original timestamps and checksums. The 42 reconstructed upstream binaries are newly built. All checksums and version receipts are revalidated when assembling this report.




How the binary sanity check works
Every executable is checked with components, embedded Go build tags, and Go’s implementation/stub file selection. A local probe configures no detectors and disables retries, so it makes no detector metadata requests and exits with the expected empty-detector error.
The PR additionally logs compiled_detectors before that exit; the runner checks this list exactly. Upstream main does not expose that per-detector runtime list, so its inventory check uses the embedded tags and selected source files. These checks establish build composition, not successful detection in each provider’s native environment. Kubernetes builds also report the deprecated k8snode alias for k8s_api.
